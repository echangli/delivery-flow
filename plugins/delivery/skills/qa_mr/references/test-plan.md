## Тест-кейсы
| # | REQ | Приоритет | Шаги | Ожидание | Оракул | Техника/линза | Статус | Тип |
|---|-----|-----------|------|----------|--------|---------------|--------|-----|
| 1 | REQ-01 | P0/P1/P2 | {{шаги}} | {{ожидание}} | {{TICKET_AC / SPEC / DEV_NOTE / EXISTING_BEHAVIOR / REFERENCE_PARITY / OPEN}} | {{EP/BVA/authz/…}} | ⏳NOT-RUN | smoke / regression |

- **Оракул** — источник ожидания, пиши **до** прогона: `TICKET_AC` · `SPEC` · `DEV_NOTE` (автор/дата) ·
  `EXISTING_BEHAVIOR` (текущее поведение как baseline) · `REFERENCE_PARITY` · `OPEN`. Нет оракула — кейс не годен.
  **Код фиче-ветки и юнит-тесты разработчика — не оракул** (тавтология): источник тогда `OPEN` → спросить владельца,
  PASS не ставить.
- **Техника/линза** — по какой технике спроектирован кейс (см. `test-design-techniques.md`), не «на глаз».
- **Статус:** `✅PASS / ≈PASS-EQ / ❌FAIL / ⚠️PARTIAL / ⛔BLOCKED / ⏳NOT-RUN`. **NOT-RUN не молчать** — незапущенный
  кейс явно `⏳NOT-RUN`, не пропускать и не приравнивать к FAIL. `≈PASS-EQ` — критерий наблюдён на подменённом
  значении с **записанным** доказательством эквивалентности; `PASS-EQ`/`PARTIAL`/`BLOCKED` в `PASS` не сворачивать.
- **Негативы — дифференциально**, если есть baseline (прод/main-слот → ветка-слот): сравнивай коды/
  сообщения/сайд-эффекты, а не суди по одной ветке.
