# Property Catalog — переиспользуемые properties

Проверять этот список перед тем, как придумывать новое имя property. Если по смыслу подходит существующее —
использовать его, не создавать синоним (`amount_usdt` вместо `amount_usd`, `location` вместо `place` и т.п. —
так возникают дубли, которые потом сложно чистить).

> 🔧 **ADAPT: это стартовый шаблон, а не ваш каталог.** Ниже — только **универсальные** сквозные свойства,
> которые встречаются в любом продукте. Дополните его своими сквозными свойствами (те, что уже висят на
> нескольких событиях вашей таксономии) и заполните колонку «Где используется» — какие события у вас их
> несут. Список из живой таксономии снимается через MCP платформы аналитики (см. последний пункт ниже).

| Property | Тип | Смысл | Где используется |
|---|---|---|---|
| `place` | string | Место в интерфейсе, откуда произошло действие — когда одно и то же событие/блок встречается в нескольких местах | ⟪ADAPT⟫ |
| `object_name` | string | Дискриминатор для общих (generic) событий, покрывающих несколько типов объектов одним event_type | ⟪ADAPT⟫ |
| `amount` | number | Сумма в локальной валюте пользователя | ⟪ADAPT⟫ |
| `amount_usd` | number | Сумма в USD (единый формат для всех денежных событий) | ⟪ADAPT⟫ |
| `currency` | string | Код локальной валюты (ISO) | ⟪ADAPT⟫ |
| `provider` | string | Внешний провайдер операции (платёжный/иной) | ⟪ADAPT⟫ |
| `network` | string | Сеть/канал проведения операции | ⟪ADAPT⟫ |
| `method` | string | Способ/метод, выбранный пользователем | ⟪ADAPT⟫ |
| `<entity>_id` | string \| number | Идентификатор сущности домена (единый паттерн на все типы сущностей) | ⟪ADAPT⟫ |
| `is_<flag>` | boolean | Булев признак состояния/варианта (`is_recommended`, `is_repeat`, `is_manual`) | ⟪ADAPT⟫ |
| `<feature>_enabled` | boolean | Состояние тумблера именованной фичи (когда фича имеет собственное UI-имя) | ⟪ADAPT⟫ |
| `<feature>_amount` | number \| null | Числовое значение настройки фичи; `null` когда фича выключена | ⟪ADAPT⟫ |
| `chip_index` | number | Порядковый номер элемента в горизонтальном ряду чипов/карточек, начиная с 1 | ⟪ADAPT⟫ |

## Общие правила использования

- **Деньги:** всегда `amount` + `currency` (локальная валюта) и/или `amount_usd`. Никогда не создавать `amount_<токен>` для конкретных валют.
- **Место показа:** если фича/блок может появляться в ≥2 местах интерфейса — сразу проектировать через `place`, а не через отдельные event_type на каждое место.
- **Generic-события:** если действие универсально (копирование, шеринг, лайк) и уже есть общее событие (`copied_info`) — переиспользовать его с новым значением `object_name`, не создавать `copied_<new_object>`.
- **ID сущностей:** единый паттерн `<entity>_id` (`snake_case`), а не `<entity>Id`/`id_<entity>`. Заводя новый тип сущности — идти по тому же паттерну.
- Полный список уже сконфигурированных project-wide event properties смотреть через MCP платформы аналитики (в примере — `mcp__amplitude__get_properties`, `propertyType: event`, без `eventType`) — если скилл имеет доступ к MCP; иначе ориентироваться по `taxonomy-snapshot.md` и этому каталогу.
