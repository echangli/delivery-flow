# Пример 1 — блок-призыв к действию в двух местах интерфейса

Показывает: паттерн `place` для одного и того же блока в двух точках интерфейса, минимальный набор из
3 событий с одной общей property, явное решение "когда НЕ нужно отдельное событие".

> Пример **обезличенный** — по мотивам реальной разметки. Замените на разборы своих прошлых спек: каждая
> должна заканчиваться разделом «Чему учит этот пример».

## Контекст
Блок-призыв к действию ("<название блока>") встречается в двух местах:
- `banner` — баннер вверху главного экрана, с кнопкой закрытия ✕
- `bottomsheet`/`modal` — поверх экрана-каталога, без ✕ (боттомшит на мобиле, popup на вебе — **единое значение `modal` для обеих платформ**)

## 🆕 CREATE

| event_type | Display name | Trigger | Properties |
|---|---|---|---|
| `shown_<block>` | Shown \<Block\> [Front] | Показ модалки (реальное появление, не монтирование компонента) | `place`: `modal` |
| `clicked_<block>_button` | Clicked \<Block\> Button [Front] | Клик по кнопке призыва к действию | `place`: `banner` \| `modal` |
| `closed_<block>` | Closed \<Block\> [Front] | Клик ✕ на баннере | `place`: `banner` |

## Важные решения (зафиксированы явно, а не оставлены на усмотрение фронта)
- `modal` — одно значение и для боттомшита (моб), и для попапа (веб). Не заводить `bottomsheet`/`popup` как разные значения — платформенное различие не имеет аналитического смысла здесь.
- `shown_<block>` стреляет **при реальном появлении блока**, не при монтировании компонента — частая ловушка, из-за которой событие может фигурировать без реального показа пользователю.
- `closed_<block>` — только для `banner`. У `modal`-варианта отдельного closed-события **нет** — закрывается свайпом/навигацией, что не несёт дополнительного аналитического смысла по сравнению с уходом со страницы.
- `place` — единственная property, одинаковая на все три события (не изобретать разные имена вроде `source`/`location`/`origin` для того же смысла).

## Чему учит этот пример
- Минимальный набор событий на фичу — 3, а не 6 (не "по событию на каждое место × каждое действие").
- Явно объяснять, где события **намеренно нет** — экономит раунд вопросов от фронтендера.
