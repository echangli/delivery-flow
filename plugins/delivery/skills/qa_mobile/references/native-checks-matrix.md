# native-checks-matrix — что гонять, что это доказывает

Ядро `/qa_mobile`: нативные проверки, которых веб-только `qa_mr` не может. Каждая = **рецепт · оракул ·
эмулятор/девайс · трейс**. Глубину бери по импакту MR (переписан бридж → вся матрица; правка копи → ни
одной). Техники/оракулы — из `../qa_mr/references/test-design-techniques.md`. `⟪ADAPT⟫` = проектное
значение (пакет, схема, хосты, ключи хранилища, объект бриджа). Конкретные имена в рецептах ниже
(маркеры logcat, классы активити, методы бриджа, строки dev-панели) — worked-примеры под один нативный
шелл; переложи под свой (имена — из репо, не по памяти).

Предусловия: приложение запущено + залогинено (temp-wallet, `cdp-recipes.md §4`), CDP форварднут (`§0`).

## Свип бриджа

Все методы, что страница может попросить у нативного шелла. Драйвь через CDP как страница; смотри
нативный сайд-эффект.
- **Рецепт:** `is-supported` на каждый метод (round-trip доказывает достижимость бриджа); затем каждый
  метод через `cdp-recipes.md §3`. Сайд-эффекты: буфер (`copy-to-clipboard` → чип буфера в IME / вставка),
  хаптика (`start-haptic-feedback` — физически), тема (`set-theme` персистит преф, без reload;
  `system_theme_get` отдаёт тему ОС), внешняя ссылка (`open-browser` → `dumpsys window mCurrentFocus` =
  Chrome CustomTabActivity), шаринг (`open-share-dialog` → ChooserActivity), keep-awake
  (`set-keep-screen-awake` → экран не гаснет; глаза юзера на реальном девайсе), OAuth (`login-by-oauth`
  → CustomTab на sso_url).
- **Не-бридж, но в свипе:** WalletConnect (`⟪ADAPT: wc:⟫` URL) и file chooser перехватываются во фрагменте
  (`shouldOverrideUrlLoading` / `onShowFileChooser`), это не методы бриджа.
- **Оракул:** ноль ошибок бриджа в logcat (`Malformed request`/`Internal error`/`Unsupported method`
  отсутствуют); visible-действия открывают нужную активити. **Трейс:** `mCurrentFocus`, маркеры logcat.

## Деплинк — delivered (не переигрывается)

- **Рецепт:** `adb -s $D shell "am start -n <pkg>/.<Activity> -a android.intent.action.VIEW -c android.intent.category.BROWSABLE -d '⟪ADAPT: app://open?dl_id=<route>&<params>⟫'"` (реальные
  значения `dl_id` — в фиче deep-links web-client: экран инструмента, чат, список позиций, dev-режим, …).
  Доставку подтверди в logcat `app->web … set-deeplink`. Затем фон (`keyevent HOME`) → возврат (релонч) и
  reload (CDP `Page.reload`): **считай `set-deeplink` — 0 новых = не переигран.**
- **Экранирование инъекции:** пошли деплинк со значением, несущим `"` (`…?x="}]);window.__pwned=42;//`,
  заквотируй под девайс-шелл). Должен прийти как данные — `window.__pwned` чист, код не выполнился.
- **Оракул:** доставлен 1×; 0 переотдач на фон/reload; инъекция экранирована. **Нюанс:** приложение само
  персистит последний роут (напр. выбранный актив) — reload, показавший тот же экран, это персист роута,
  НЕ переигрывание деплинка; суди по счётчику `set-deeplink`, не по визуалу. **Трейс:** число доставок
  `set-deeplink`.

## Деплинк — durable / отложенная доставка

- **Рецепт (durable):** `am force-stop` → холодный старт с деплинком → полли pending-store, пока WebView
  грузится: `adb -s $D shell run-as <pkg> cat shared_prefs/⟪ADAPT: 21bcfdb…xml⟫ | grep <slot-key>`. Ключ
  есть + `set-deeplink`=0 = **отложен (deferred)** до готовности; затем доставлен; затем ключ убран после
  ack. **Смерть процесса:** убей, пока ключ на диске (до ack) → ключ переживает → чистый релонч **без**
  деплинка → он переотдан из store.
- **Рецепт (deferred/OneLink):** пошли `⟪ADAPT: https://…onelink.me/…⟫` → репозиторий диплинков НЕ должен
  его парсить (`set-deeplink`=0) — уходит в атрибуцию-SDK. Истинный пост-инсталл-deferred (клик до
  установки → матч атрибуции на первом запуске) требует **реального зарегистрированного** OneLink +
  бэкенда SDK; синтетический не резолвится → фиксируй как ограничение.
- **Оракул:** деплинк переживает не-готовый WebView и смерть процесса; OneLink отдан в SDK, не распарсен.

## Over-install (логин/хранилище переживают апдейт)

Самый страшный класс — смена формата хранилища может отобрать доступ у всех, и на чистой установке это не
видно.
- **Рецепт:** старую сборку `install -r` → логин + задать пароль кошелька (руки юзера) → слепок **ДО**:
  `run-as <pkg> ls -la shared_prefs` + `cat` шифро-файлов (записать имена ключей + sha256 шифротекстов).
  Новую сборку поверх (`install -r`, без `pm clear`). Проверить, что залогинен / кошелёк открывается.
  Слепок **ПОСЛЕ**: легаси-файл исчез, флаг миграции выставлен, ключи на месте, шифротексты изменились =
  lazy-перешифровка (или не изменились = уже новый формат). Дешифровку подтверди бриджем
  `encrypted_storage_get` (печатай только `type:ok`/длину, **никогда** сам секрет). Второе чтение =
  идемпотентно.
- **Оракул:** логин/ключи целы; формат мигрировал; в logcat НЕТ маркеров потери (`discardUnreadable`/
  `aead-null`/`Internal error`). **Нюанс scope:** соц-логин держит сессию в cookie → бридж-шифрохранилище
  у него пустое; рискованный путь миграции населяется только кошельковыми аккаунтами — гоняй с аккаунтом
  с паролем кошелька, чтобы задействовать. **Трейс:** `user_id`, имена файлов, sha шифротекстов.

## Permissions / камера (класс краша Android 8.0/8.1)

- **Рецепт:** триггерь запрос permissions из реального file/camera-инпута (dev-панель — см. File chooser)
  ЛИБО, на старом WebView эмулятора, где SPA не грузится, запусти активити напрямую:
  `adb root` + `am start -n <pkg>/.<PermissionsActivity> --es <REQ_ID_key> <v> --esal <PARAMS_key>
  PERMISSION_CAMERA`. Выдай (юзер/тап) → `dumpsys package <pkg> | grep 'CAMERA: granted'`.
- **Оракул:** нет краша на API 26/27 (`Only fullscreen opaque activities can request orientation` /
  IllegalStateException отсутствуют), системный диалог показан, разрешение выдано. Гоняй на **API 26 И 27**.

## Safe-area / клавиатура

- **Рецепт:** девайс с вырезом + нав/жест-баром. Через CDP замерь `getBoundingClientRect().top *
  devicePixelRatio` верхнего контента vs пиксели выреза (из `dumpsys window | grep DisplayCutout`), и
  `bottom` нижнего нава vs верх нав-бара. Сфокусируй текстовый инпут (напр. поле чата) →
  клавиатура вверх → прочитай `window.innerHeight` до/после (adjustResize ужимает) и `rect.bottom` инпута
  vs вьюпорт.
- **Оракул:** верхний контент ниже выреза; нижний нав выше нав-бара; сфокусированный инпут виден над
  клавиатурой (`keyboardCoversInput:false`). Safe-area переменные на `html`/`body` могут быть 0 (дефолты)
  — инсеты применяются на app-root; суди по замеренным позициям на экране, не по переменным.

## Экраны ошибок (полная матрица требует рут-стенд)

- **Дёшево подтверждается:** реальный сбой загрузки главного фрейма (транзиентный VPN-флак на эмуляторе)
  показывает нативный «Something went wrong» + «Try Again». Retry перезагружает.
- **Полная матрица (5xx документ→нативный экран / 4xx→страница / суб-ресурс→нет / чужой хост→нет):**
  нужен сетевой прокси, подменяющий статусы, а он — **системный CA** (см. `mobile-harness.md §1`). CDP
  `Fetch.fulfillRequest` НЕ триггерит `onReceivedHttpError` — не используй. Задокументируй пороги из
  диффа и пометь матрицу как ждущую рут-стенд.

## Шаринг (busy не залипает)

- **Рецепт:** `open-share-dialog` с полной тройкой картинки (base64+name+mime) → ChooserActivity. Шар
  дважды подряд; шар → reload/back → шар снова; шар + немедленный reload (резерв в очереди); неполная
  картинка (base64 без name) → деградирует в текст, без утечки резерва.
- **Оракул:** каждый шар открывает sheet; ни один не отклонён по busy (Logger-маркеры идут в Sentry, не в
  logcat — суди по поведению). Старый баг: шар залипал в busy до перезапуска — не должен воспроизводиться.

## OAuth + смерть процесса

- **Рецепт:** `adb shell settings put global always_finish_activities 1` (Don't keep activities). Начни
  соц-логин (юзер тапает аккаунт) → во время редиректа активити уничтожается → при возврате проверь
  logcat: **новый pid** стартовал + `app->web … set-oauth-result`. Верни `always_finish_activities 0`.
- **Оракул:** токен не потерян, логин применился после пересоздания процесса (дошёл до домашней поверхности).

## Пуш-промпт (свежая установка — ровно один раз)

- **Рецепт:** `pm clear` → свежий запуск на **API 33+** (промпт POST_NOTIFICATIONS только ≥Android 13) →
  счётчик `adb logcat | grep GrantPermissionsViewModel … POST_NOTIFICATIONS` для приложения.
- **Оракул:** ровно один промпт за чистый прогон свежей установки. **Риск в отчёт:** запрос срабатывает
  на каждую page-session, гейт только «уже granted» (нет латча «спросить раз») → вторая полная загрузка
  документа при неотвеченном разрешении покажет снова; подтверди, что реальный онбординг делает одну
  загрузку до ответа юзера.

## File chooser / fullscreen / download (dev-панель)

MR шипит `FileChooserGate`/`FullscreenGate`/`DownloadPolicy`, но у продового web-client может не быть
`<input type=file>` (KYC уходит к стороннему провайдеру в Chrome Custom Tab — gate приложения там НЕ
задействован). Используй **dev-панель «Native checks»** фронтендера (тестовая ветка с реальным `<input
type=file>` внутри WebView):
- **Вход в dev mode:** деплинк `⟪ADAPT: app://open?dl_id=devMode⟫` → Профиль(аватар) → «Dev Mode» →
  «Native checks» → «Open».
- **File chooser:** кнопки Single/Multiple/Images/Camera триггерят `onShowFileChooser` → нативный пикер
  (`DocumentsUI PickActivity`, запущенный приложением, `Bridge Connected: true` — НЕ Chrome). Тест: выбор
  из галереи; **Google Drive (size-less файл — главный пункт: старые сборки отклоняли файлы без размера)**
  → должен приняться с метаданными; отмена (BACK → возврат чистый, не залипает); Multiple (мульти-выбор);
  второй пикер поверх первого. **Grid-селекция: через DPAD** (MIUI tap-квирк, `mobile-harness.md §3`).
- **Оракул:** пикер открывает приложение (не Chrome); Drive size-less принят (`Picked: 1` с
  name/type/size); отмена не залипает. **Fullscreen:** Enter → заполняет экран, back-жест выходит,
  `Change events` растёт. **Download:** триггерь загрузку → `DownloadPolicy`/`DownloadRequester`
  (sandboxed-загрузки могут быть инертны для смотрящего — проверь «Last attempt»/«URL responds» в панели).
