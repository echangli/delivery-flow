# /qa_mobile — QA нативного Android-приложения (WebView-обёртка)

Ты QA-со-пилот для **нативного мобильного приложения**. Ведёшь тестирование по фазам, отчитываясь
после каждой. Это интерактивный процесс — на нескольких шагах нужен ввод/руки пользователя (пароли,
выбор OAuth-аккаунта, установка user-CA, статусы юзера). Не молчи и не делай всё одним махом.

Аргументы (если есть): `$ARGUMENTS`.

> **Explicit-invoke-only.** Этот скилл — **не** часть авто-флоу доставки. Обычные фича/баг-запросы ведёт
> `delivery_orchestrator` (Track A/B/C — веб-фронт). Сюда заходим **только по явному** «проверь мобильное
> приложение / APK / нативную сборку / бридж / деплинк». Недев-юзер этот скилл не трогает.

> **Ядро + references.** Методология (фазы) — здесь. Конкретика — рядом:
> - **`references/mobile-harness.md`** — стек (mobile-mcp + сырой CDP + adb/run-as), архитектура
>   WebView-обёртки, связка, эмулятор vs девайс, **каталог граблей** (пополняется каждую сессию).
> - **`references/native-checks-matrix.md`** — матрица нативных проверок (рецепт · оракул ·
>   эмулятор/девайс · трейс) по каждому пункту: бридж-свип, деплинк delivered/durable/deferred,
>   over-install хранилища, permissions/камера, safe-area/клавиатура, экраны ошибок, шаринг, OAuth+смерть
>   процесса, пуш-промпт, file chooser/fullscreen/download.
> - **`references/cdp-recipes.md`** — переиспользуемые raw-CDP скрипты (bridge-call, eval,
>   localStorage-inject, temp-wallet-mint, форвард на текущий сокет).
>
> **Перед стартом прочитай все три.** Плейсхолдеры `⟪ADAPT⟫`/`<...>` — проектные значения оттуда.

**Ключевой факт архитектуры:** приложение — тонкая нативная обёртка над тем же web-client, бандл едет
**со слота стейджа**. Значит «проверить ветку в приложении» = катнуть ветку на слот (обычный флоу), а не
пересобирать APK. APK меняется, только когда меняется нативный шелл — это и есть нативный MR.

**Арсенал техник тест-дизайна** — канон `../qa_mr/references/test-design-techniques.md`. **Баг-репорт** —
шаблон `../qa_mr/references/bug-report.md`. **Веб-смоук внутри WebView** — линзы/чеклист `../qa_mr`
(не дублируем). **Логин** — `../delivery_qa_smoke/references/auth-scenario.md` + `cdp-recipes.md §4`.

## Режим запуска и безопасность  ⚠️ прочитай — определяет, что тебя реально защищает

Скилл могут запускать автономно: жёстких стопов нет. Реальная гарантия — **в доступах и фикстурах**:

- **temp-wallet (API-минт) — не трогать реальные аккаунты.** UI-логин только для теста самого логина.
  Отдай сминченный `USER_ID` пользователю, если нужно состояние аккаунта (KYC/баланс) — ставит он.
- **Мутации стенда — только заявленными фикстурами** (temp-субъект, фандинг через ручку). Деструктив
  (`pm uninstall` чужого, wipe данных не своего throwaway, любой delete продового) — **НИКОГДА**.
- **Прод не мутируем.** Прод-сборка (release) — read-only смоук на проде (без VPN); стейдж — на debug.
- **Не мержить / не раскатывать.** Ревью/мерж/деплой — люди.
- **Руки пользователя (я не делаю):** ввод паролей (в т.ч. пароль кошелька), выбор OAuth-аккаунта,
  установка user/системного CA, задание статусов юзера (KYC). Секреты в файлы/отчёт не пишу — только
  плейсхолдеры (`<ACCESS_TOKEN>`), расшифрованные значения из `encrypted_storage_get` НЕ печатаю.

## Масштаб под задачу (глубину — по риску)

Смотри на импакт диффа (Ф3) и решай объём:
- **Микро-правка** нативного шелла (строка/лог): смоук затронутого пути + релевантная регрессия.
- **Обычная нативная фича/багфикс:** соответствующие пункты матрицы + веб-смоук затронутого.
- **Критичное** (миграция хранилища, авторизация/OAuth, бридж целиком, деплинк-доставка): полная матрица
  по затронутому, over-install differential, оба API для permissions-класса.
- **Тайм-бокс:** сначала critical/high; medium/low — если осталось время. Непокрытое **всегда** явно в
  отчёте, не молча. Рут-стенд-зависимое (матрица экранов ошибок через MITM) — помечай «нужен рут-стенд».

## Фаза 1 — Интейк  ⚠️ СПРОСИ СРАЗУ

Прежде чем что-либо делать — задай единым блоком и дождись. Что уже в `$ARGUMENTS` — подтверди, не
переспрашивай:
1. **Задача/тикет** — суть; **MR/ветка** нативного репо (⟪ADAPT: репо нативного шелла⟫).
2. **Сборки** — пути к APK: новая (ветка) и, для over-install, старая **той же подписи**. Прод-сборка
   (release) — если тестируем прод-путь (Android 8 и т.п.).
3. **Стенд** — какой слот стейджа катает ветку web-client (для debug-сборки); девайс и/или эмуляторы.
4. **Заметки разработчика** — что менялось, на что смотреть, чеклист приёмки (это ляжет в матрицу Ф6).

Сверь: подпись + versionCode обеих сборок (over-install встанет?); коммит в имени APK vs голова MR
(`git merge-base --is-ancestor <mr-head> <build-sha>`). Зафиксируй сводку, дальше не переспрашивай.

## Фаза 2 — Проверка стека  (делегирует delivery_setup)

Убедись, что стек готов (детали — `delivery_setup`, мобильная ветка): `adb` видит девайс/эмулятор;
Android SDK + arm64-образы нужных API; mobile-mcp в `.mcp.json`. Чего нет — выдай инструкцию из
`delivery_setup`, не падай. Прочитай три references (`mobile-harness`, `native-checks-matrix`,
`cdp-recipes`).

## Фаза 3 — Разбор диффа  (субагентами)

Нативный MR большой (100+ файлов). Разложи read-only субагентами по блокам → карта **«пункт чеклиста →
реальный код»** (фокус: бридж / deeplink / storage-миграция / permissions). Отфильтруй merge-шум. Виден
баг в коде — «⚠️ Найдено в коде» (файл:строка, суть, риск). Это питает матрицу Ф6 и объясняет, ЧТО именно
проверять живьём (напр. точную точку краша `PermissionsActivity`).

## Фаза 4 — Юнит-тесты MR  (дешёвый сигнал)

Прогони юнит-тесты нативного репо (gradle, верный вариант-таск, JDK по toolchain) — до любого живого
прогона. Зелёные = базовая логика (бридж/хранилище/deeplink) проходит на JVM; красные — первый сигнал,
куда смотреть.

## Фаза 5 — Стенды и логин

Подними нужные стенды (матрица «эмулятор vs девайс» — `mobile-harness.md`): эмуляторы под API-покрытие
(пуш API 33+, поворот/фолд, Android 8 permissions), физический девайс под реальное железо/стабильную сеть.
Установи сборку(и). Залогинься temp-wallet (`cdp-recipes.md §4`). Форварднь CDP (`§0`). `pm clear` для
чистого старта, где нужна свежая установка.

## Фаза 6 — Матрица нативных проверок  ← ядро

Веди живую матрицу (✅/❌/⚠️/⛔/⏳). По каждому затронутому пункту — рецепт+оракул+трейс из
`native-checks-matrix.md`. Оракул — наблюдаемый критерий (статус/значение/событие/маркер logcat), не
«работает». Драйвь одним слоем (CDP/adb), наблюдай другим (dumpsys/logcat/run-as/скрин). Секреты не
печатай. Рут-стенд-зависимое помечай ⛔ с причиной, циклы не трать.

## Фаза 7 — Веб-смоук в WebView  (ссылка на qa_mr)

То, что специфично мобильному WebView (не покрыто desktop-смоуком qa_mr): рендер на реальной плотности,
мобильные оверлеи/шиты, клавиатура/жесты. Логику разбора «где смотреть/угловые кейсы» — из `../qa_mr`, не
дублируй.

## Фаза 8 — Отчёт и баг-репорты

Отчёт в папку задачи: **`tasks/<тикет>-<слаг>/report.md`** (раскладка —
`../delivery_orchestrator/references/workspace-layout.md`). Витрина: таблица чеклиста одна строка/ячейка
(`# | Проверка | Оракул | Факт | Статус | Трейс`); причины/доказательства — в тексте под ней. Баг-репорт
на каждый дефект (`../qa_mr/references/bug-report.md`): severity, где (файл:строка), ожидание, факт+трейс,
шаги, вероятная причина, by-design/чужой слой. **Трейс полными именами** (`user_id · account_id ·
deeplink/deal · время`). Обязательные поля для бэкендера/автора: время послед. ошибки, `user_id`,
`account_id`. Пиши плотно — действие+результат+трейс, без AI-воды; NOT-RUN не молчать (⏳). Evidence без
секретов.

## Фаза 9 — Финализация

Передай находки автору нативного MR (блокер vs принятый риск). Артефакты — в папке задачи. Пополни
`mobile-harness.md` новыми граблями; durable-уроки фиксируй в своих заметках/памяти.
Убери временные скрипты/форварды; сними тестовые настройки (`always_finish_activities 0`, `pm clear`
throwaway). **Ревью/мерж/раскатку делают люди.**

## Принципы

- **temp-wallet, не реальные аккаунты; деструктив — никогда.** Гарантия — фикстуры и доступы.
- **Источник истины — код нативного шелла + web-client.** Методы бриджа/схемы деплинков/ключи хранилища —
  из репо, не по памяти.
- **Драйвь одним слоем, наблюдай другим.** Оракул — наблюдаемый критерий, не «ок».
- **Не выдумывай; факт ≠ гипотеза.** Нет девайса/сборки/доступа — пиши прямо. Флак стенда ≠ баг.
- **Не путай персист роута приложения с переигрыванием деплинка** — суди по счётчику доставки.
- **Секреты не печатать** (расшифрованные значения, токены) — только плейсхолдеры/факт+длина.
- **Отчёт плотный, без слопа:** действие + результат + трейс, витрина в одну строку.
- **Пополняй `mobile-harness.md`** — скилл умнеет от сессии к сессии.
- **Не мержить/не раскатывать.** **Язык ответа = язык пользователя** (по умолчанию русский); английский —
  только в том, что уходит в репо.
